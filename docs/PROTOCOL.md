# 音声回収の実装メモ

初代NotePinで観測した範囲と、同梱コードが扱う形式に限定しています。公式仕様・全機種対応の定義ではありません。機器設定、FW、工場／診断APIは扱いません。

## 通信

| 役割 | GATT UUID |
|---|---|
| Service | `00001910-0000-1000-8000-00805f9b34fb` |
| Write Without Response | `00002bb1-0000-1000-8000-00805f9b34fb` |
| Notify | `00002bb0-0000-1000-8000-00805f9b34fb` |

対象の所有者署名を送信し、RSA応答から得た80バイトのセッション情報を、所有者のRSA秘密鍵で復号します。鍵32バイト・nonce12バイト・AAD12バイト・検証用暗号文24バイトを扱い、ChaCha20-Poly1305の検証結果が`PLAUD.AI`と一致することを確認します。その後、所有者ハンドシェイクを送り、成功応答からprotocol versionを読みます。認証を迂回する仕組みではありません。[認証素材](AUTHENTICATION.md)

## 録音ファイルの読み出し

認証後の要求は要求番号u32 LEを前置し、セッション暗号化して送ります。

- 録音状態：`01 03 00`。応答の位置10が録音フラグ、位置11のu32 LEが現在録音ID（フラグ1の場合）。
- 範囲要求：`01 1c 00` + 録音ID:u32 LE + 開始位置:u32 LE + 要求長:u32 LE。
- データ応答：`02` + 録音ID:u32 LE + 位置:u32 LE + 長さ:u8 + データ。

最初に先頭512バイトを取得します。その後はファイル先頭基準の`512 + 80 × 完全フレーム数`から再開します。通知を位置順に組み立て、穴を飛び越えたり、通知境界を音声フレーム境界とみなしたりしません。

`0xffffffff`の位置通知は、現在録音では追いついた目印として扱い、新しいデータを待ちます。過去録音の完了は、要求したサイズまで欠落・端数なく受信し、WAVと位置の保存が完了してから記録します。

## 復号とWAV

| ファイル内位置（0始まり） | 用途 |
|---|---|
| 0..7 | `PLAUD.AI` |
| 132..143 | 音声用nonce（12バイト） |
| 144..147 | フレーム長u32 LE。同梱実装は80バイトを要求 |
| 256..511 | RSA PKCS#1 v1.5で包まれた32バイト音声鍵 |
| 512以降 | 80バイト単位の暗号化音声 |

各80バイトをChaCha20で復号し、Opusをデコードします。対応形式は1フレーム320サンプル＝16 kHz・モノラル・20 msです。Androidは15,000フレーム＝5音声分ごとにWAVを確定します。

## 過去録音の一覧ページ

要求は`01 1a 00` + 要求UID:u32 LE + start:u32 LE（本実装は0）+ single:u8（本実装は0）。要求番号・暗号化を除いた応答本体は次の構造です。

| 位置 | 内容 |
|---|---|
| 3 | 要求UID:u32 LE |
| 7 | 全ページの総件数:u16 LE |
| 9 | このページの開始位置:u16 LE |
| 11以降 | 録音ID:u32 LE + サイズ:u32 LE + 版別の末尾 |

項目幅は、認証のprotocol versionが1なら8バイト、2〜6なら9バイト、それ以外なら10バイト。本文の長さから推測しません。要求UID・総件数の一貫性・連続したページ順・同一IDの重複を検査し、受信数が総件数に達した場合だけ一覧を完了とします。同一ページの一致した再送は二重計上しません。

一覧は差分であり、全録音の存在証明ではありません。未応答は空一覧ではありません。初代NotePinで分割ページの実機試験は未完了です。

実装入口：Androidの`Protocol`／`HistoryProtocol`／`CollectorService`、Pythonの`direct_probe.py`／`history_probe.py`／`inventory_codec.py`。
